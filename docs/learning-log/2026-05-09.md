## 今日のテーマ

`src/modules/users/user.entity.ts` の中身を題材に、TypeScript のクラス定義の基礎を理解する。

```ts
export class User {
    id!: string;
    email!: string;
    name!: string;

    constructor(data: User) {
        Object.assign(this, data);
    }
}
```

---

## 学んだこと

### 1. `!`（Definite Assignment Assertion / 確定代入アサーション）

**何のためにある？**

TypeScript の `strictPropertyInitialization` が有効だと、クラスのプロパティは「宣言時に初期化」または「コンストラクタで代入」しないとエラーになる。

```ts
export class User {
    id: string;  // ❌ Property 'id' has no initializer...
}
```

`!` を付けると「**初期化は外部で必ず行うので心配しないで**」とコンパイラに伝えられる。

```ts
export class User {
    id!: string;  // ✅ OK
}
```

**いつ使う？**

クラスのプロパティで、コンストラクタ以外（外部のフレームワークやライブラリ）から値が代入されるとき。

- バックエンドの TypeORM エンティティ（DB から行を読み込んで代入）
- 今回のフロントエンドのドメインモデル（`Object.assign` でまとめて代入）

### 2. `!` を「使う / 使わない」の判断

| 場面 | 書き方 |
| --- | --- |
| クラスで、必ず値が入るプロパティ | `id!: string` |
| クラスで、無いこともあるプロパティ | `nickname?: string` |
| `interface` / `type` で型だけ定義 | `id: string`（`!` は不要・付けられない） |

`interface` / `type` は「型の設計図」だけで実体を作らないので、初期化チェック自体が起きない。

### 3. `constructor(data: User)` + `Object.assign(this, data)` パターン

**意味:**

```ts
constructor(data: User) {
    Object.assign(this, data);
}
```

- `constructor` は `new User(...)` 時に呼ばれる特別なメソッド
- `Object.assign(コピー先, コピー元)` は標準 JS API。第 2 引数のプロパティを第 1 引数にコピーする
- `this` は「いま生成されている User インスタンス自身」
- 結果として `data.id`, `data.email`, `data.name` が `this` にまとめてコピーされる

**普通に書くと:**

```ts
constructor(id: string, email: string, name: string) {
    this.id = id;
    this.email = email;
    this.name = name;
}
```

→ プロパティが増えるたびに引数も `this.xxx = xxx` も増える。冗長。

**`Object.assign` なら:**

```ts
constructor(data: User) {
    Object.assign(this, data);
}
```

→ プロパティが増えても**この 3 行は不変**。クラスフィールドを増やすだけで済む。

### 4. このパターンが効いている場所

`src/modules/auth/auth.repository.ts:16` で、API レスポンスを `User` インスタンスに変換している:

```ts
const { user, token } = result.data;
return { user: new User(user), token };
```

- API から返ってきた `user` は **ただの JSON オブジェクト**（プレーンな型）
- `new User(user)` で **`User` クラスのインスタンス**に変換
- 将来 `User` クラスにメソッド（`getDisplayName()` など）を追加すると、インスタンス経由で呼べるようになる

→ クラスにする最大のメリットは、**データに振る舞い（メソッド）を持たせられる**こと。

## 補足: 今回の `User` は TypeORM のエンティティではない

ファイル名が `user.entity.ts` なので一見 TypeORM のエンティティに見えるが、このプロジェクトはフロントエンド（React + Vite）。バックエンドは別リポジトリ（`notion-clone-api/`）にある。

つまり今回の `User` は:

- バックエンドの TypeORM エンティティ ❌
- **フロントエンドのドメインモデル**（API レスポンスをラップする用途）✅

`!` + `Object.assign` というパターン自体は、TypeORM 固有ではなく **TypeScript クラスの一般的な書き方**。バックエンドでもフロントエンドでも通用する。
